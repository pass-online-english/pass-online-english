# Anki デッキの作成・修正

命名規則の全文は `docs/ANKI_DECK_RULES.md`。要点は以下。

## デッキ名の作り方

```
YYYY-MM-DD 授業復習          例: 2026-09-06 授業復習
YYYY-MM-DD 宿題復習          例: 2026-09-06 宿題復習
YYYY-MM-DD 授業復習（二次試験対策）   内容が特殊なときだけ括弧で補う
```

**日付は「その教材がどの授業のものか」を表す。カードを作った日ではない。**

宿題は次の授業の直前に提出されるため、カード化する日は授業日の1〜5日後になる。
この作成日をデッキ名にすると「どの授業の宿題か」が失われる。
判断がつかないときは推測で日付を決めず、利用者に確認する。

## 階層

2段まで。`授業デッキ › 内容のまとまり` で終える。

- 親と同じ意味の層を作らない（`2026-08-24 宿題復習 › 20260824 宿題復習 › 例文` は不可）
- 子が1つしかない層を作らない
- 科目名・生徒名・「英検準2級プラス」のような括りのトップレベルデッキを新設しない
- 1つのデッキに複数回分の授業や、授業と宿題を混ぜない
- サブデッキ名に日付を入れない（親が持っている）
- 既存教材の続きは新しいトップレベルデッキを作らず、既存デッキのサブデッキにする

`LEAP` `シンプル英語構文｜全162文` `英文解釈` は教材デッキ。構造に意味があるので触らない。

## タグ

全ノートに2種類付ける。デッキを畳んでも情報が残る。

- 授業日: `lesson-YYYYMMDD` または `hw-YYYYMMDD`
- 内容分類: `vocab` `grammar` `reading` `jp2en` など（サブデッキ名に対応）

## 既存デッキを修正するとき

`.apkg` / `.colpkg` は SQLite を含む ZIP。**書き換えてよいのは2か所だけ。**

| テーブル | 列 | 内容 |
|---|---|---|
| `decks` | `name` | デッキ名 |
| `cards` | `did` | カードの所属デッキ |

以下は絶対に書き換えない。学習履歴が消える。

- `revlog` テーブル（解答1回ごとの記録）
- `cards` の `type` `queue` `due` `ivl` `factor` `reps` `lapses`
- `notes` テーブル

学習データはカードに紐づいていてデッキには紐づかないため、
この2か所だけの変更なら履歴は完全に保たれる。

編集後は必ず、元ファイルと `revlog` / `notes` / カードのスケジュール列のハッシュが
一致することを確認してから渡す。

## 検品

```bash
python3 scripts/anki/check_deck.py deck.apkg              # 違反を一覧表示
python3 scripts/anki/check_deck.py deck.apkg --fix out.apkg  # 機械的に直せるものを修正
```

`--fix` が直すのは階層と日付表記のみ。複数回分が同居しているデッキのように
内容の判断が要るものは NG として報告するだけで、勝手に分割しない。

デッキを生成したあとは必ずこのチェックを通してから利用者に渡す。

## コレクション全体を差し替えるとき

1デッキの `.apkg` を再インポートしても、既存カードのデッキ移動は反映されない
（Anki のインポートは既存ノートを更新するだけで、所属デッキを変えない）。
既存の学習履歴つきコレクションの構造を直す場合は、
**コレクション全体（`.colpkg`）を書き換えて完全置換**してもらう。

利用者に伝える手順:

1. Anki の設定 → ネットワーク → 自動同期をオフ
2. `ファイル → エクスポート` でバックアップ
3. `ファイル → インポート` で修正版 `.colpkg`（現在のコレクションを置き換える）
4. 同期 → 分岐を聞かれたら**アップロード**（修正したのは手元なので）
5. 他の端末で同期 → そちらは**ダウンロード**
